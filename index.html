一、專題介紹

💡 專題用途

提供一個隨身常駐於 LINE 聊天室的 24/7 生活智慧對話助理。使用者無需下載額外 App 或切換至付費 AI 網頁，在日常熟悉的通訊軟體中即可發問生活知識、旅遊推薦、草稿撰寫與靈感解答。

👥 使用對象

所有 LINE 日常高頻度使用者（學生、上班族、家庭成員），尤其適合需要在手機上以簡潔中文快速獲得答案、不耐繁複操作的人群。

⚡ 核心功能

「繁中語意問答與排版收斂引擎」：整合 Google Gemini 最新 Flash 模型，設定台灣繁中語境，實作 500 字長度安全收斂、標點截斷、移除 Markdown 雙星號粗體標籤，以及貼圖與純表情已讀不回防洗版機制。

🔄

二、改善版核心紀錄（原本問題、修改內容、前後差異、重測結果）

改善重點：依照作業規範，自第一版為起點完成「輸入防呆引導、不支援訊息提示與內建離線功能清單」，全面覆蓋使用者異常輸入之健全防護。
項目 詳細說明
1. 原本問題
(Original Problem)		 • 輸入不完整問題：使用者若傳送純空白、空格或僅輸入「推薦」、「幫我」等模糊短詞，第一版會直接發送至 Gemini API，造成 Token 浪費且 AI 容易誤判產生偏離回答。
• 不支援格式無反饋：第一版僅註冊文字與貼圖處理器。若使用者傳送語音、位置、影片、檔案等訊息，機器人直接已讀不回，使用者無法判斷機器人是否發生故障。
• 缺乏離線指令指南：初次加入好友之使用者無從得知推薦發問句型，缺乏快捷說明。
2. 修改內容
(The Changes)		 • 實作空白與不完整輸入攔截器：檢查 user_text.strip()，針對空白字串與「推薦」、「幫我」、「查詢」等關鍵字提供親切的分類選項引導。
• 註冊全格式不支援處理器：新增 ImageMessageContent、AudioMessageContent、VideoMessageContent、LocationMessageContent 與 FileMessageContent 處理邏輯，明確告知功能限制並引導打字。
• 新增內建離線功能指南：支援輸入「說明」、「功能」、「/help」，免呼叫 AI 即時回覆繁中功能導覽與範例。
3. 前後差異
(Before vs After)		 • 改善前 (v1.0.0)：遇到非文字格式完全無反饋；模糊輸入易浪費 AI 配額；無內建幫助指令。
• 改善後 (v1.0.1)：訊息格式 100% 覆蓋反饋；模糊字主動提醒補充細節；提供即時說明選單，大幅提升使用者體驗與防呆能力。
4. 重新測試結果
(Retest Results)		 • 測試空白輸入與「推薦」均能精準觸發補充提示。
• 測試傳送語音與位置資訊均獲得親切不支援提示，並引導打字。
• 正常長句提問依然由 Gemini 穩定回答，排版清爽自然，三大情境全數通過。

四、開發過程紀錄

第一階段：需求與計畫擬定
確立從 Echo Bot 升級至 AI Smart Bot 的核心方向，規劃 Flask 後端架構與金鑰隔離機制。
第二階段：核心後端開發與 AI 串接
使用 line-bot-sdk v3 實作 Webhook，串接 Google Gemini API，設計繁中提示詞與四重模型降級佇列。
第三階段：邊界與編碼修復
解決 Windows CP950 編碼列印 Emoji 造成的崩潰問題；加入貼圖已讀不回與 500 字安全句尾截斷演算法。
第四階段：改善版功能升級 (v1.0.1)
新增輸入防呆檢驗、不支援訊息類型（語音/位置/檔案/影片）即時提示、離線說明指令，完成完整單元測試。
第五階段：雙大腦本地模型與即時聯網升級 (v1.2.0)
導入本機 RTX 3050 運行的 Qwen 2.5 3B (Ollama)，結合 ddgs 即時網際網路搜尋引擎，突破 2025 知識截止限制，實現 2026 最新時效問答與零 API 費用雙大腦架構。

五、AI 協作歷程與除錯經驗

1. 使用的 AI 工具

Google Antigravity AI Agent、Google Gemini 3.8 Flash、Git / GitHub CLI、Microsoft Edge Headless PDF 引擎。

2. 代表性指令 (Prompt)

「請以 Python 3.12 與 LINE Messaging API v3 為架構，串接 Google Gemini API。
要求：
1. 設計四重模型自動降級佇列（gemini-flash-latest -> gemini-3.8-flash -> gemini-3.5-flash -> gemini-flash-lite）。
2. System Prompt 控制輸出為台灣繁體中文，字數限制 250~450 字，移除 Markdown 雙星號。
3. 實作標點符號安全句尾截斷演算法，確保在 500 字上限內不會話說到一半中斷。」

3. 一次檢查或修正 AI 產出的經驗

真實除錯經驗：
在初版測試時，AI 產出的原始程式碼直接在 Windows 終端機中 print() 包含 Emoji 的 Gemini AI 回覆，導致 Windows 預設的 cp950 / Big5 編碼拋出 UnicodeEncodeError: 'cp950' codec can't encode character 造成伺服器直接崩潰離線。
修正過程：經由檢視伺服器日誌定位問題後，手動要求 AI 在 app.py 啟動最前緣加入底層標準輸出重定向：
sys.stdout.reconfigure(encoding="utf-8", errors="replace")
成功徹底解決跨平台終端編碼崩潰問題，伺服器從此穩定常駐。

情境 輸入內容 預期結果 實際結果 狀態

情境二：輸入不完整 「 」（純空格） 或 「推薦」 不呼叫 Gemini 浪費 Token，即時提示使用者輸入不完整，並提供分類選項提醒補充。 空白輸入回覆：「您輸入的訊息好像是空白的喔！...」；「推薦」回覆：「哈囉！收到您的推薦需求～請問您想要哪一種類型的推薦呢？1. 美食 2. 旅遊 3. 電影...」 通過

七、心得、已知限制與下一步

🌱 學到的收穫

  • 深入掌握 LINE Webhook HMAC-SHA256 簽章安全機制與事件派送模型。
  • 學會 Google Gemini 生成模型參數（System Instructions、Max Output Tokens）與例外降級設計。
  • 體驗 AI 協作開發的高效流程，同時體認到對 AI 產出程式碼進行邊界條件檢查與平台相容性審查的必要性。

⚠️ 已知限制與下一步改善

  • 無多輪對話記憶：目前仍為無狀態 (Stateless)，下階段規劃引入 Redis 記錄 Session 上下文。
  • 本地運行依賴：目前依賴本機開機與 Cloudflare 穿透，下階段將容器化部署至 Google Cloud Run。
  • 尚未支援圖文選單 (Rich Menu)：下階段將在 LINE 後台建立六宮格視覺快捷鍵。
